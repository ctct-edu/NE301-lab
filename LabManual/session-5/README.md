# Session 5: ドキュメント作成

## 前提

- Session 4 で ToDo アプリの全機能が完成していること
- `starter/` フォルダを作業フォルダにコピーしていること

---

## 演習 1: README ファイルの作成（20 分）

この演習では、AI を活用して README.md ファイルを作成します。README はプロジェクトの「顔」であり、他の人がプロジェクトを理解するための最初の手がかりになります。

### ステップ 1: AI に README を生成させる

チャットパネルを開き、以下のプロンプトを入力します。

**入力するプロンプト：**

```txt
@todo.py の README.md を作成してください。
以下の内容を含めてください。
- プロジェクトの概要
- 機能一覧
- 必要な環境
- 使い方（起動方法と操作方法）
```

### ステップ 2: 生成された README を確認する

AI が生成した README を確認します。以下の項目が含まれているか確認します：

| 項目           | 内容                                             |
| -------------- | ------------------------------------------------ |
| プロジェクト名 | ToDo アプリ                                      |
| 概要           | 何をするアプリか（1-2 文）                       |
| 機能一覧       | タスクの追加、表示、完了切り替え、削除、CSV 保存 |
| 必要な環境     | Python 3.x                                       |
| 使い方         | `python todo.py` で起動、メニューから操作        |

AI の生成したものをそのまま使うのではなく、内容を確認して修正します。自分のプロジェクトに合っていない部分は書き換えます。

### ステップ 3: README を編集する

AI が生成した内容を元に、以下の点を修正・追加します：

- 実際の出力例を追加する
- 必要に応じて説明を補足する
- 不要な情報を削除する

### ステップ 4: ファイルに保存する

`README.md` という名前で保存します。

- ファイル名は `README.md`（すべて大文字）が慣例
- Markdown 形式で書く（見出し、リスト、コードブロックなど）
- VS Code のプレビュー機能（`Ctrl + Shift + V` / `Cmd + Shift + V`）で確認できる

## 演習 2: ユーザーマニュアルの作成（20 分）

この演習では、技術的な知識がない人でも操作できるユーザーマニュアルを作成します。README が開発者向けなのに対し、ユーザーマニュアルはエンドユーザー向けです。

### ステップ 1: AI にマニュアルを生成させる

以下のプロンプトを入力します。

**入力するプロンプト：**

```txt
ToDo アプリのユーザーマニュアルを作成してください。
技術的な知識がない人でも操作できるように、
以下の内容を含めてください。

- アプリの起動方法
- 各機能の使い方（手順と画面例）
- よくある質問（FAQ）
```

### ステップ 2: 生成されたマニュアルを確認する

ユーザーマニュアルに求められるポイント：

- 専門用語は避けるか、説明を加える（「ターミナル」→「黒い画面」など）
- 操作手順を具体的に示す（「1. 〇〇をクリック」「2. △△ と入力」など）
- 画面の状態を示す（CLI の場合は出力例）
- 予想される疑問に先回りして答える（FAQ）

### ステップ 3: マニュアルを編集する

以下の点を確認して修正します：

- 専門用語がないか
- 手順が具体的か
- 画面例があるか
- 困ったときの対処法があるか

### ステップ 4: ファイルに保存する

`USER_MANUAL.md` という名前で保存します。

## 演習 3: ドキュメントから実装を再現（15 分）

この演習では、作成したドキュメント（要件定義書・設計書）を AI に渡して、コードを再生成させます。良いドキュメントは AI にも人間にも理解しやすいことを体験します。

### ステップ 1: 新しいフォルダを作成する

```sh
mkdir todo_app_v2
cd todo_app_v2
```

この新しいフォルダで、ドキュメントだけを元に AI にコードを生成させます。

### ステップ 2: AI エージェントに実装を依頼する

GitHub Copilot の場合は Agent モード、Cursor の場合は Composer を使用します。

**GitHub Copilot:**

- チャットパネルで Agent モードに切り替え

**Cursor:**

- `Ctrl + I`（Mac: `Cmd + I`）で Composer を開く

以下のプロンプトを入力します。

**入力するプロンプト：**

```txt
以下の要件定義と設計書に基づいて、ToDo アプリを実装してください。

[Session 2 で作成した要件定義書と設計書を貼り付け]
```

AI エージェントはファイルの作成・編集を自動で行います。要件定義書と設計書が明確であれば、AI は正確に実装できます。曖昧な部分があると、AI が独自の解釈で実装してしまいます。

### ステップ 3: 生成されたコードを確認する

生成されたコードを元のコードと比較します。

確認ポイント：

- 機能が揃っているか
- データ構造が設計書通りか
- 実行して動作するか

良いドキュメントは AI も理解しやすい＝人間も理解しやすいです。ドキュメントを書くことは、将来の自分や AI への投資です。
