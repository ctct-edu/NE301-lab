# Session 5: ドキュメント作成

## 前提

- Session 4 で ToDo アプリの全機能が完成していること
- `exercise/` フォルダの中身を作業フォルダにコピーしていること

## この演習で使う AI 機能

この演習では、用途に応じて以下の AI 機能を使い分けます。

| 機能               | 用途                                  | 操作                                                                                                             |
| ------------------ | ------------------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| チャット           | README やマニュアルの生成、レビュー   | GitHub Copilot: `Ctrl + Shift + I`（Mac: `Cmd + Shift + I`）/ Cursor: `Ctrl + L`（Mac: `Cmd + L`）               |
| インライン編集     | コメント・docstring のピンポイント修正 | GitHub Copilot: `Ctrl + I`（Mac: `Cmd + I`）/ Cursor: `Ctrl + K`（Mac: `Cmd + K`）                               |
| エージェントモード | ドキュメントからコードを自動生成      | GitHub Copilot: チャットパネルで Agent モードに切り替え / Cursor: `Ctrl + I`（Mac: `Cmd + I`）で Composer を開く |

## 演習 1: 成果物のドキュメントを作成する（20 分）

この演習では、AI を活用して README.md ファイルとユーザーマニュアルを作成します。README は開発者向けのプロジェクト説明、ユーザーマニュアルはエンドユーザー向けの操作説明書です。

### ステップ 1: チャットパネルを開く

使用する AI 機能: **チャット（Chat パネル）**

作業フォルダの `todo.py` を開いた状態で、チャットパネルを開きます。

- **GitHub Copilot**: サイドバーのチャットアイコンをクリック、または `Ctrl + Shift + I`（Mac: `Cmd + Shift + I`）
- **Cursor**: `Ctrl + L`（Mac: `Cmd + L`）

### ステップ 2: AI に README を生成させる

チャットパネルに以下のプロンプトを入力して送信します。

**入力するプロンプト：**

```txt
@todo.py の README.md を作成してください。
以下の内容を含めてください。
- プロジェクトの概要
- 機能一覧
- 必要な環境
- 使い方（起動方法と操作方法）
```

`@todo.py` と入力すると、ファイルの内容を AI に渡すことができます。

### ステップ 3: 生成された README を確認する

AI が生成した README を確認します。以下の項目が含まれているかチェックしてください。

| 項目           | 内容                                             |
| -------------- | ------------------------------------------------ |
| プロジェクト名 | ToDo アプリ                                      |
| 概要           | 何をするアプリか（1-2 文）                       |
| 機能一覧       | タスクの追加、表示、完了切り替え、削除、CSV 保存 |
| 必要な環境     | Python 3.x                                       |
| 使い方         | `python todo.py` で起動、メニューから操作        |

AI の生成したものをそのまま使うのではなく、内容を確認して修正することが重要です。

### ステップ 4: README を編集・保存する

AI が生成した内容を元に、以下の点を修正・追加します。

- 実際の出力例を追加する（メニュー画面やタスク一覧の表示例）
- 必要に応じて説明を補足する
- 不要な情報を削除する

作業フォルダに `README.md` という名前で保存します。

- ファイル名は `README.md`（すべて大文字）が慣例です
- Markdown 形式で書きます（見出し、リスト、コードブロックなど）
- VS Code のプレビュー機能（`Ctrl + Shift + V` / `Cmd + Shift + V`）で表示を確認できます

### ステップ 5: AI にユーザーマニュアルを生成させる

使用する AI 機能: **チャット（Chat パネル）**

続けてチャットパネルに以下のプロンプトを入力して送信します。

**入力するプロンプト：**

```txt
@todo.py のユーザーマニュアルを作成してください。
技術的な知識がない人でも操作できるように、
以下の内容を含めてください。

- アプリの起動方法
- 各機能の使い方（手順と画面例）
- よくある質問（FAQ）
```

### ステップ 6: 生成されたマニュアルを確認する

AI が生成したマニュアルを確認します。ユーザーマニュアルに求められるポイントは以下の通りです。

- 専門用語は避けるか、説明を加える（「ターミナル」→「黒い画面」など）
- 操作手順を具体的に示す（「1. 〇〇を入力」「2. Enter を押す」など）
- 画面の状態を示す（CLI の場合は出力例）
- 予想される疑問に先回りして答える（FAQ）

### ステップ 7: マニュアルを編集・保存する

AI が生成した内容を元に、以下の点を確認して修正します。

- 専門用語が使われていないか
- 手順が具体的に書かれているか
- 画面例（出力例）が含まれているか
- 困ったときの対処法が書かれているか

作業フォルダに `USER_MANUAL.md` という名前で保存します。

### ステップ 8: コメントと docstring を改善する

使用する AI 機能: **チャット（Chat パネル）**

README とマニュアルが「プロジェクトの外側に向けた説明」だとすれば、コメントと docstring は「コードを読む人（将来の自分を含む）」への説明です。最後に `todo.py` のコード内ドキュメントも AI にレビューしてもらいましょう。

チャットパネルに以下のプロンプトを入力して送信します。

**入力するプロンプト：**

```txt
@todo.py のコメントと docstring を改善してください。
以下の方針でお願いします。
- 「何を」ではなく「なぜ」を書く
- docstring には引数と戻り値の説明を入れる
- 当たり前すぎるコメントは削除する
```

AI の提案を確認します。`new_id = max(...) + 1` のような箇所に「ID の重複を防ぐため」といった **「なぜ」** を説明するコメントが追加されているはずです。

提案をすべて受け入れる必要はありません。特定の関数だけピンポイントで直したい場合は、対象の関数を選択してインライン編集（GitHub Copilot: `Ctrl + I` / Cursor: `Ctrl + K`）で修正するのが便利です。

また、今後の改善アイデアを `TODO` コメントとしてコード中に残しておくのもおすすめです。テキスト本編で紹介した `TODO` / `FIXME` / `HACK` / `NOTE` タグを使い分けると、他のメンバー（や将来の自分）に意図が伝わりやすくなります。

```py
# TODO: 期限設定機能を追加する（WANT 機能）
# TODO: タスクの優先度（高/中/低）に対応する
```

完成したら、`Ans/` フォルダの `README.md` と `USER_MANUAL.md` と見比べて確認してください。

## 演習 2: ドキュメントから実装を再現（20 分）

この演習では、Session 2 で作成した要件定義書と設計書を AI に渡して、コードを再生成させます。良いドキュメントは AI にも人間にも理解しやすいことを体験します。

### ステップ 1: 新しいフォルダを作成する

ターミナルで以下のコマンドを実行して、新しいフォルダを作成します。

```sh
mkdir todo_app_v2
cd todo_app_v2
```

この新しいフォルダで、ドキュメントだけを元に AI にコードを生成させます。

### ステップ 2: AI エージェントモードを開く

使用する AI 機能: **エージェントモード**

エージェントモードは、AI がファイルの作成や編集を自動で行ってくれる機能です。これまでのチャットやインライン補完と違い、AI が自分でファイルを作成して実装を進めてくれます。

お使いのツールに応じて、以下の操作でエージェントモードを開きます。

**GitHub Copilot の場合:**

1. チャットパネルを開く（`Ctrl + Shift + I` / `Cmd + Shift + I`）
2. チャットパネル上部のドロップダウンで「Agent」モードに切り替える

**Cursor の場合:**

1. `Ctrl + I`（Mac: `Cmd + I`）で Composer を開く

### ステップ 3: 要件定義書と設計書を貼り付けて実装を依頼する

エージェントモード（または Composer）に以下のプロンプトを入力して送信します。

**入力するプロンプト：**

```txt
以下の要件定義と設計書に基づいて、ToDo アプリを実装してください。

[Session 2 で作成した要件定義書と設計書の内容をここに貼り付け]
```

`[Session 2 で作成した要件定義書と設計書の内容をここに貼り付け]` の部分には、Session 2 で完成させた `要件定義テンプレート.md` と `設計テンプレート.md` の内容をコピー＆ペーストしてください。

AI エージェントがファイルの作成・編集を自動で行います。処理が進む様子を確認しましょう。

### ステップ 4: 生成されたコードを確認する

生成されたコードを元のコード（Session 4 で完成した `todo.py`）と比較します。

以下のポイントを確認してください。

- 要件定義書で定めた機能がすべて揃っているか
- 設計書で定めたデータ構造になっているか
- `python todo.py` で実行して、正しく動作するか

要件定義書と設計書が明確であれば、AI は正確に実装できます。曖昧な部分があると、AI が独自の解釈で実装してしまいます。

良いドキュメントは AI にも人間にも理解しやすい、ということをこの演習で体験できたはずです。ドキュメントを書くことは、将来の自分や AI への投資です。
